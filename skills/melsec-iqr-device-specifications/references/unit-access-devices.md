# ユニットアクセスデバイス／CPUバッファメモリアクセスデバイス詳細仕様

iQ-Rの Un\G, U3En\G, U3En\HG の個別仕様。インテリジェント機能ユニットのバッファメモリやCPUバッファメモリへ直接アクセスするためのデバイス。

## ユニットアクセスデバイス (Un\G)

- **種別**: ワード
- **記号**: Un\G
- **デフォルト点数**: 最大268435456点（CPUユニットが扱える最大値。実際の点数はユニットにより異なる）
- **最大使用範囲**: 変更不可
- **設定単位**: -
- **表記**: 10進数
- **用途**: 基本ベースユニット／増設ベースユニットに装着されているインテリジェント機能ユニットのバッファメモリへ、CPUから直接アクセス

### 指定方法

`U<ユニット先頭I/O番号上位2桁>\G<バッファメモリアドレス>` の形式。

例: `U5\G11`, `U0\G10`

| 指定項目 | 指定する値 |
|---------|-----------|
| Un | インテリジェント機能ユニットの先頭入出力番号を3桁表現した場合の上位2桁（00H〜FFH） |
| Gn | バッファメモリアドレス 0〜268435455(10進数) |

例: 先頭I/Oが X/Y1F0 のユニット → Un = `1F` → `U1F\G10` のように指定

### 動作・注意事項

- **使い分け**: FROM/TO 命令と等価機能を提供するが、Un\G を直接演算式に使えるため記述が簡潔になる
- **処理速度のヒント**: プログラム内でユニットアクセスデバイスを2回以上使用する場合、まずデータレジスタ(D)等に格納してから FROM/TO 命令でプログラムの1箇所のみ読み書きすると処理速度が早くなる
- **リフレッシュ機能との衝突**: リフレッシュ機能使用時、プログラムで直接リフレッシュ対象先メモリへ書込みすると、CPUがリフレッシュ実行時に対象先メモリを上書きするため意図しない動作になる。リフレッシュ機能使用時は、リフレッシュ元メモリにデータを書き、対象先メモリに直接書き込まないこと

### バックアップ/リストア・トラッキング

- **バックアップ/リストア**: 可 / 可
- **トラッキング転送**: 転送可（グローバルのみ、ローカル対象外）

## CPUバッファメモリアクセスデバイス (U3En\G)

- **種別**: ワード
- **記号**: U3En\G
- **デフォルト点数**: 最大268435456点
- **最大使用範囲**: 変更不可
- **設定単位**: -
- **表記**: 10進数
- **用途**: マルチCPUシステムの各CPU間でのデータ書込み／読出し、Ethernet機能などCPUの内蔵機能で使用するメモリにアクセス

### 指定方法

`U3En\G<アドレス>` の形式。

| 指定項目 | 指定する値 |
|---------|-----------|
| Un（CPUユニットの入出力番号） | 1号機=3E0, 2号機=3E1, 3号機=3E2, 4号機=3E3 |
| G（CPUバッファメモリのエリア） | 通常エリア=G |
| n（CPUバッファメモリアドレス） | 0〜268435455(10進数) |

例: 2号機CPUの定周期通信エリア4095番 → `U3E1\G4095`

### バックアップ/リストア・トラッキング

- **バックアップ/リストア**: 可 / 可（**ただし「システムで使用するエリアはリストア後に上書きされることがある」**）
- **トラッキング転送**: 転送可

## CPUバッファメモリ定周期通信エリア (U3En\HG)

- **種別**: ワード
- **記号**: U3En\HG
- **デフォルト点数**: 最大12288点
- **最大使用範囲**: **変更可**（CPUバッファメモリエリア内）
- **設定単位**: -
- **表記**: 10進数
- **用途**: マルチCPU間の定周期通信エリア。U3En\G よりも高頻度・確定的なタイミングでCPU間通信を行うためのエリア

### 指定方法

`U3En\HG<アドレス>` の形式。

例: `U3E2\HG1024` → 3号機CPUの定周期通信エリア1024番

### バックアップ/リストア・トラッキング

- **バックアップ/リストア**: 可 / 可（システム使用エリアはリストア後に上書きされることあり）
- **トラッキング転送**: 転送可

## マルチCPUシステムでの使用上の注意

### バッファメモリの読出し/書込み（管理外ユニット）

マルチCPU構成では、自CPUが管理していないインテリジェント機能ユニット（**管理外ユニット**）への操作に制約がある：

| 操作 | 管理ユニット | 管理外ユニット |
|------|-------------|----------------|
| バッファメモリの読出し（FROM／Un\G使用） | 可 | 可 |
| バッファメモリへの書込み（TO／Un\G使用） | 可 | **不可** |
| 出力(Y)のON/OFF | 可 | CPU内部ではON/OFFされるが**実出力には反映されない** |
| リンクダイレクトデバイス（Jn\X等）でのアクセス | 可 | 不可 |

つまり、Un\Gを使った**書込みは自CPUの管理ユニットに対してのみ有効**である点が大きな注意点。

### 同期立上げと立上り確認

マルチCPU間で同期立上げを設定していない場合、**SM220〜SM223（1〜4号機準備完了）** を使って各CPUの立上りを確認するインタロックプログラムを書くことを推奨。

立ち上がっていないCPUに対して命令を実行した場合は無処理となる。

## ユニット先頭I/O番号の指定の仕方（Un\G用）

ユニット先頭I/O番号は、ベースユニット上のスロットおよびユニット形名により決定される。エンジニアリングツールの「ユニット構成」「システム構成」画面で確認するのが確実。

例:
- ベース1段目スロット0（先頭I/O = X/Y0）→ Un = `00`
- ベース1段目スロット1で前段が16点ユニット（先頭I/O = X/Y10）→ Un = `01`
- ベース1段目スロット2で前段までが32点（先頭I/O = X/Y20）→ Un = `02`

I/O割付（自動・固定／指定）はシステムパラメータの「I/O割付設定」で確認・変更する。
