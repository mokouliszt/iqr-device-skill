# インデックスレジスタ／ファイルレジスタ／リフレッシュデータレジスタ詳細仕様

iQ-Rの Z, LZ, R, ZR, RD の個別仕様。

## インデックスレジスタ (Z)

- **種別**: ワード
- **記号**: Z
- **デフォルト点数**: 20点
- **最大使用範囲**: 0〜23点（点数設定で変更可）
- **設定単位**: 2点単位
- **表記**: 10進数
- **用途**: デバイスのインデックス修飾（デバイス番号のオフセット指定）に使用

### 修飾範囲

16ビットによる修飾。修飾範囲は **-32768〜32767**。

### 指定方法

`<修飾対象デバイス番号>Z<インデックスレジスタ番号>` の形式。

例: `D0Z0`（D0 + Z0 の値 のデバイスにアクセス）, `D100Z10`

### ZZ表現（32ビット範囲のインデックス修飾）

`Zn` と連続した次の `Z(n+1)` を組として32ビットの修飾範囲を扱える方法。`LZ` の範囲では指定不可。隣接するZ点が他用途と重ならないよう注意。

### インデックス修飾が可能なデバイス

**16ビットによるインデックス修飾**: X, DX, Y, DY, M, L, B, F, SB, V, S, T(接点/コイル/現在値), LT, ST, LST, C, LC, D, W, SW, SM, SD, Jn\X, Jn\Y, Jn\B, Jn\SB, Jn\W, Jn\SW, Un\G, U3En\G, U3En\HG, R, ZR, RD, P(割込みポインタとしては不可), I(同左), BL, BLn\S, J, U, K, H

**32ビットによるインデックス修飾**: M, B, SB, T, LT, ST, LST, C, LC, D, W, SW, Jn\B, Jn\W, Un\G, U3En\G, U3En\HG, R, ZR, RD, K, H

`Jn\X`, `Jn\Y`, `Jn\SB`, `Jn\SW` および ネットワークNo./入出力番号指定側 は32ビットによる修飾不可。

### バックアップ/リストア

- **バックアップ/リストア**: 可 / 可（**ローカルインデックスレジスタを含む**）

### トラッキング転送

- 転送可（グローバル）

### 注意事項

- インデックスレジスタ(Z)とロングインデックスレジスタ(LZ)の合計点数が **24ワード** となるよう設定する
- ローカルインデックスレジスタはプログラム実行時に退避/復帰されるため、他のローカルデバイスとは扱いが異なる
- 16ビット符号なしデータを扱う命令で Z に 32768〜65535 を格納してインデックス修飾しても、修飾範囲は -32768〜32767 となるため意図した動作にならない。32768以上のオフセットは LZ を使うこと
- SIL2プロセスCPUおよび安全CPU（の安全プログラム）では指定不可

## ロングインデックスレジスタ (LZ)

- **種別**: ダブルワード
- **記号**: LZ
- **デフォルト点数**: 2点
- **最大使用範囲**: 0〜12点（点数設定で変更可）
- **設定単位**: 1点
- **表記**: 10進数
- **用途**: 32ビット範囲のインデックス修飾

### 修飾範囲

32ビットによる修飾。修飾範囲は **-2147483648〜2147483647**。

### 指定方法

`<修飾対象デバイス番号>LZ<番号>` の形式。

例: `D0LZ0`, `D100LZ1`

### バックアップ/リストア

- **バックアップ/リストア**: 可 / 可（ローカルロングインデックスレジスタを含む）

### トラッキング転送

- 転送可

### 注意事項

- Z と LZ の合計点数が 24 ワードを超えないよう設定
- ZZ表現（32ビット修飾）の代替として LZ を使うほうが、Z点の重複を意識しなくてよく安全
- SIL2プロセスCPU、安全CPUの安全プログラムでは使用不可

### インデックスレジスタ設定画面（CPUパラメータ）

`[CPUパラメータ] → [メモリ/デバイス設定] → [インデックスレジスタ設定]`

| 項目 | 内容 | 設定範囲 | デフォルト |
|------|------|---------|------------|
| 合計点数 | Z＋LZの合計点数表示 | - | - |
| インデックスレジスタ(Z) | Zの点数 | 0〜24点（2点単位） | 20点 |
| ロングインデックスレジスタ(LZ) | LZの点数 | 0〜12点（1点単位） | 2点 |
| ローカルインデックスレジスタ(Z) | ローカル用Z点数 | 0〜24点（1点単位） | 0点 |
| ローカルロングインデックスレジスタ(LZ) | ローカル用LZ点数 | 0〜12点（1点単位） | 0点 |
| 先頭(Z) | ローカルZの先頭番号 | 0〜23 | 0 |
| 先頭(LZ) | ローカルLZの先頭番号 | 0〜11 | 0 |

## ファイルレジスタ (R / ZR)

- **種別**: ワード
- **記号**: R / ZR
- **デフォルト点数**: 0点
- **最大使用範囲**: ファイルレジスタファイルサイズによる（ZR0〜(ファイルサイズ(ワード)-1)）
- **設定単位**: -（ファイル容量により変動）
- **表記**: 10進数
- **用途**: 拡張用ワードデバイス。実体はデバイス/ラベルメモリのファイル格納エリアにあるファイルレジスタファイル

### 指定方法は2種類

#### ブロック切替え方式（記号: R）

使用しているファイルレジスタ点数を **32K点(R0〜R32767) 単位** で区切って指定。複数ブロックを使用している場合は **RSET命令** で使用するブロックNo.を切り替える。

- Rの範囲: R0〜R32767
- ただし、ファイルレジスタファイルサイズが64Kバイト未満、または64Kバイトの倍数でなく最後のブロックを指定している場合は、デバイス番号上限がブロックサイズ(ワード)-1 となる

#### 連番方式（記号: ZR）

32K点を超えるファイルレジスタを連続したデバイス番号で指定。複数ブロックを連続的に扱える。

- ZRの範囲: ZR0〜(ファイルレジスタファイルサイズ(ワード)-1)

### 設定手順

1. CPUパラメータでファイルレジスタの使用方法を設定
2. プログラム別のファイルレジスタを使用する場合、あらかじめファイルレジスタファイルとなるデバイスメモリを作成しておく必要がある（GX Works3）
3. 全プログラム共通のファイルレジスタを使用する場合、ファイルレジスタ設定で設定したファイル名・容量のファイルレジスタファイルが作成される（容量未設定時は手順2と同様にデバイスメモリ作成→シーケンサ書込み時に容量設定）

### バックアップ/リストア

- **バックアップ/リストア**: 可 / 可

### トラッキング転送

- 転送可（**ただし、トラッキングデバイス/ラベル設定で「一括転送」を指定した場合は対象外**で、明示的に指定が必要）

### 注意事項

- プログラム別のファイルレジスタを使うと、モニタや現在値変更時に意図しないデータが読み書きされる場合がある（プログラム間でのモニタおよびEND処理でのみ実行可能なため、特定のファイルレジスタを直接指定できない）
- 指定プログラムモニタ機能を使えば、対象タイミングを指定可能

## リフレッシュデータレジスタ (RD)

- **種別**: ワード
- **記号**: RD
- **デフォルト点数**: 512K点
- **最大使用範囲**: -（デフォルトのまま使用するのが基本。点数変更可）
- **設定単位**: -
- **表記**: 10進数
- **用途**: ユニット間のリフレッシュ用データレジスタ。リフレッシュメモリに割り付けて使用
- **動作**:
  - リフレッシュ専用エリアにあり、ネットワークユニットや高速通信ユニット等のリフレッシュ先として使用
  - リフレッシュメモリの設定で割付・容量を指定
- **バックアップ/リストア**: 可 / 可
- **トラッキング転送**: 転送可

## CPU機種ごとの差異

R120CPU/R120ENCPU、SIL2プロセスCPU(R120PSFCPU)、安全CPU(R120SFCPU)など120系の大容量CPUでは、ファイルレジスタ／リフレッシュデータレジスタの設定可能範囲が大きい。

R120CPUに拡張SRAMカセット(NZ2MC-16MBS, 16Mバイト)を装着すると、ファイルレジスタ含む各種デバイスの最大点数が大幅に拡張される。
